# Аудит архітектури лабораторної 1

Чорновик відтворено зі знімка `history-kit 2.zip` і перевірено 09.10.2026. Це відтворюваний
аудит чорновика, а не твердження, що недоліки були знайдені під час давнішої незалежної
розробки. Точний [вивід до виправлень](../reports/lab1-audit-before.txt) збережено окремо.

`npm run deps:check` знайшов чотири порушення залежностей; `npm run lint` — два читання
`process.env` поза дозволеним місцем. Три головні архітектурні проблеми виправлено окремо:

| Проблема                                               | Порушення [spec.md](../spec.md)                                                       | Стійке виправлення                                                                                                                       | Коміт     |
| ------------------------------------------------------ | ------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| `tickets/service → volunteers/ports`                   | Обхід публічного API модуля (R1) і дублювання перевірки відсутнього майстра.          | `tickets` використовує `VolunteerService` через `volunteers/index.ts`; межу закріплює `module-public-api-only`.                          | `9b7cb71` |
| `tickets/domain → volunteers/domain` заради `Category` | У чорновій spec спільне для двох доменів поняття належало лише одному модулю (R1/R2). | Spec визначає `Category` у `shared`; обидва модулі імпортують його звідти. Межі закріплюють `domain-is-pure` і `module-public-api-only`. | `8dfce71` |
| `tickets/domain → fastify`                             | Доменне правило переходу знало тип і статус HTTP (R2).                                | `assertTransition` кидає `DomainError('CONFLICT')`; HTTP-шар перетворює його на 409, smoke-тест перевіряє доменний тип.                  | `69c7ec9` |

Поза топ-3 файл `platform/version.ts` читав `process.env` поза `config`. ESLint знайшов обидва
звернення; у коміті `e9ff957` `gitSha` передається через `AppConfig`.

Після виправлень `npm run deps:check` не знаходить порушень (24 модулі, 54 залежності), а повний
`npm run check` проходить. Makefile містить еквівалентні цілі, проте GNU Make у Windows-середовищі
перевірки не встановлено.
