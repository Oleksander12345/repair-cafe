# Стандарт: Definition of Done (власний)

Розширює DoD курсу. Зміна «готова», коли виконано **все** нижче. Перевіряється перед PR.

## Код

- [ ] `make check` зелений локально (те саме запускають hooks).
- [ ] Нових порушень архітектури немає; якщо межу свідомо змінено — спершу оновлено `spec.md` §1 і `.dependency-cruiser.cjs`.
- [ ] Немає `TODO` без номера лаби/issue, немає закоментованого коду, немає `console.log`.
- [ ] Помилки домену — `DomainError` з кодом; HTTP-статуси лише в `platform`.

## Spec і рішення

- [ ] Кожен критерій `ACn`, якого торкається зміна, має перевірку і вона зелена.
- [ ] Рішення, яке важко скасувати, має ADR (за [adr-template.md](adr-template.md)).
- [ ] Аудит `docs/audit-labN.md`: топ-3 розбіжності, кожна — з причиною і виправленням _через правило/spec/стандарт_.

## Git

- [ ] Робота у feature-гілці `labN/<тема>`, злиття тільки через PR.
- [ ] Коміти атомарні, повідомлення `тип: що зроблено` (`feat`, `fix`, `spec`, `adr`, `chore`, `docs`, `test`).
- [ ] Жодного `--no-verify`. Якщо hook заважає — виправляємо код або стандарт, а не обходимо.
- [ ] У репозиторії немає `dist/`, `node_modules/`, `.env`, згенерованих артефактів.

## Здача

- [ ] `DEFENSE.md` (≤ 1 стор.) заповнений, `/version` = sha злитого коміту.
- [ ] Шлях з AI: промпти в `ai/`, аудит виходу AI (топ-3) з посиланнями на промпт і виправлення.

## Чому саме ці пункти

Кожен пункт закриває конкретний ризик: зламана збірка у main, розмита межа модуля, рішення без
обґрунтування, «магічні» обхідні коміти. Пункти, які можна автоматизувати, автоматизовані (checks.md);
решта — ручний чекліст перед PR.
