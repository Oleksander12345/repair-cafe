# Repair Café

Система черги для [Repair Café](https://www.repaircafe.org/) — волонтерських зустрічей, де люди
приносять зламані речі (чайник, куртку, велосипед), а майстри-волонтери безкоштовно їх лагодять.

Зараз такі зустрічі ведуть на папері: черга губиться, двоє майстрів беруться за одну річ,
електронщику дістається штопання. Сервіс гарантує:

- річ потрапляє в чергу конкретної сесії, але не понад ліміт;
- **одну річ не можуть взяти двоє майстрів**, а майстер тримає не більше однієї речі в роботі;
- майстер бере лише речі зі своїх категорій (електроніка, текстиль, велосипеди…);
- статуси змінюються лише за дозволеними переходами; повторна реєстрація (подвійний клік) не створює дубль.

Лабораторна 1 створила каркас; лабораторна 2 додає сценарії на статичних даних у пам'яті та
PostgreSQL-адаптер із транзакціями й обмеженнями БД. Тип сховища обирається конфігурацією.

## Стек

Node.js 22 · TypeScript (strict) · Fastify · PostgreSQL через `pg` і SQL без ORM · ESLint +
Prettier · dependency-cruiser · husky + lint-staged · `node:test`.
Чому саме так — [adr/](adr/).

## Швидкий старт

Потрібен Node.js 22.22.1 або новіший сумісний реліз. Для запуску shell-скриптів у Windows
використовуйте Git Bash.

```bash
make install     # залежності + git hooks
make check       # усі перевірки (те саме, що й hooks)
make run         # сервер на :3000, версія = поточний git sha
make version     # {"name":"repair-cafe","version":"<sha>"}
make hook-demo   # доказ, що hook блокує брудний коміт
```

Якщо у Windows немає GNU Make, еквівалентні команди в Git Bash:

```bash
npm ci
npm run check
bash ./scripts/hook-demo.sh # після першого коміту, за чистого робочого дерева
```

У PowerShell використовуйте `npm.cmd` замість `npm`, якщо політика виконання блокує `npm.ps1`.
За замовчуванням застосунок запускається зі сховищем у пам'яті: `npm.cmd run dev`.
Для PostgreSQL потрібні `STORAGE=postgres`, явно заданий `DATABASE_URL` і попередньо
застосовані SQL-файли з [migrations/](migrations/) у порядку номерів. Застосунок сам не
змінює схему. Не застосовуйте ці міграції до наявної БД без перевірки її стану й дозволу.

`npm.cmd run test:scenarios` перевіряє прототип у пам'яті. `npm.cmd run test:db` запускає
ті самі сценарії на PostgreSQL плюс SQL-інваріанти, бюджет запитів і 503-сценарії, але
**очищає тестові таблиці між кейсами**. Тому команда вимагає `TEST_DATABASE_URL` на окрему
локальну тестову БД `repair_cafe_lab2_test_*` на нестандартному порту; звичайний `DATABASE_URL`
для неї не використовується. Подробиці контракту — у [spec.md](spec.md).
