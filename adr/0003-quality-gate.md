# 0003. Конвеєр якості: husky + lint-staged + dependency-cruiser, розподіл commit/push

- Статус: accepted
- Дата: 2026-10-05

## Контекст і проблема

Вимога курсу: hook на commit/push перевіряє формат, лінтер, smoke-тест і збірку та реально блокує
брудний коміт. Повний прогін займає ~10–15 с — якщо ставити все на кожен коміт, з'являється спокуса `--no-verify`.

## Драйвери рішення

- pre-commit — секунди, інакше його обходять.
- Архітектурні межі перевіряються машинно.
- Один і той самий набір перевірок локально і в майбутньому CI (`make check`).

## Розглянуті варіанти

1. Усі перевірки на pre-commit
2. pre-commit: швидкі по staged-файлах; pre-push: граф, smoke, збірка
3. Лише CI, без локальних hooks
4. Для архітектури: ESLint `import/no-restricted-paths` замість dependency-cruiser

## Рішення

**Варіант 2** + **dependency-cruiser**. Розподіл описано в standards/checks.md.
dependency-cruiser обрано, бо правило «модуль X не лізе у внутрішності модуля Y» записується
одним правилом з підстановкою групи (`$1`) для всіх модулів, плюс є `no-circular` і `no-orphans`.

### Наслідки

- Добре: `make hook-demo` доводить блокування; аудит Лаби 1 зловив 3 порушення.
- Погано: hooks обходяться `--no-verify` → закриваємо DoD-правилом зараз і CI в Лабі 4.
- Як перевіряємо: `make hook-demo` повертає `OK`.
