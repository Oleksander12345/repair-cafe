# 0002. Node.js 22 + TypeScript (strict) + Fastify

- Статус: accepted
- Дата: 2026-10-05

## Контекст і проблема

Потрібен HTTP-стек під курс: справжня збірка (для hook-а), валідація вхідних даних (Лаба 2),
можливість тестувати HTTP без піднятого порту (Лаба 3), прогнозована продуктивність (Лаба 5).

## Драйвери рішення

- Помилки типів ловляться до запуску (є що «збирати» на pre-push).
- Вбудована валідація запитів за схемою.
- Тестування маршрутів без мережі.

## Розглянуті варіанти

1. JavaScript + Express
2. TypeScript + Express
3. TypeScript + Fastify
4. TypeScript + NestJS

## Рішення

Обрано **TypeScript + Fastify**: `inject()` дає HTTP-тести без порту (вже використано в smoke),
JSON Schema-валідація з коробки закриває пункт «валідація» Лаби 2, без важкого DI-фреймворку.

### Наслідки

- Добре: smoke-тест /health і /version працює in-process за мілісекунди.
- Погано: екосистема middleware менша, ніж в Express; потрібно знати модель плагінів Fastify.
- Як перевіряємо: `tsc --noEmit` у pre-commit (C-03), `strict` + `noUncheckedIndexedAccess`.

## Плюси і мінуси варіантів

### JS + Express — нічого збирати, типові помилки ловляться лише в рантаймі.

### TS + Express — ок, але валідацію й тестування треба докручувати сторонніми пакетами.

### NestJS — сам нав'язує структуру модулів і DI; надлишково, і приховує ті межі, які курс просить спроєктувати самостійно.
